## 2026-11-20 — Ruby security patch (3.4.1 → 3.4.13)

**Shipped:** RepBoard production now runs Ruby 3.4.13. Render emailed that a Ruby security release fixed a remote code execution bug, and my `.ruby-version` was still on 3.4.1. PR #59 bumped `.ruby-version` and fixed a stale `Dockerfile` that still said 3.2.1 (end of life).

**Broke / got stuck on:** CI failed on the `scan_ruby` job. The log said `Brakeman 8.1.0 is not the latest version 8.1.1` and exited with code 5. My Ruby change had nothing to do with it.

**How I solved it:** `bin/brakeman` runs with `--ensure-latest`, so CI fails any time a newer Brakeman exists. A new version had come out since my last green build. I ran `bundle update brakeman --conservative` (updates only Brakeman, nothing else), checked that `Gemfile.lock` changed by exactly one line, and pushed it as a second commit on the same PR. All four checks passed. I merged and confirmed the Ruby version in the Render build log.

**Learned:** A red CI run doesn't always mean my change broke something. Read the log first. Also, a patch bump (3.4.1 → 3.4.13) is security and bug fixes only, which is why this was low risk compared to the 4.0 upgrade that broke things before.
