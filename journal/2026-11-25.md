**Shipped:**

There aren't 500 users, and there's no verification step. Any signed-up client can leave a review. I deleted the 500+ line, took "verified" out of the landing page, the PWA manifest, and the README, and changed "Join freelancers who use RepBoard…" to "Create your free profile and start collecting client reviews."
- Same PR: removed `bin-ruby-3.4.1.tar.bz2`, a 40 MB Ruby archive that got committed by accident in 0f60368 along with a ReviewsController change. Removed from the tree only, not from history.
- Opened issue #64 before making the branch, and linked it from the PR with `Closes #64`.
- Checked the live site after Render deployed. All the new text is there.

**Broke / got stuck on:**
- Typo in my branch name: `chore/remove-unverfied-claims`.
- The new line I wrote had two typos ("youre", "clent"). My grep for "verified" and "500" passed anyway.
- `git diff` stopped at a `:` and I didn't know how to get my prompt back.

**How I solved it:**
- Renamed the branch with `git branch -m` before pushing. The branch name ends up in the merge commit on main, and it's easier to fix before the push.
- Read the diff line by line and fixed the typos before committing.
- The `:` is git's pager. `q` quits it. `git --no-pager diff` prints the whole diff without it.

**Learned:**
- grep only checks that the words I removed are gone. It can't catch mistakes in the words I added. Reading the diff is the check for that.
- `git rm` removes a file from the current tree, but old commits still have it. Removing it from history would mean rewriting main and force-pushing, which wasn't worth it to save clone size.
- A deleted binary file shows `0 insertions(+), 0 deletions(-)` because git counts lines of text.
- RuboCop doesn't check ERB, and none of my specs visit the landing page. They passed, but they didn't test this change. The grep and looking at the page did.
