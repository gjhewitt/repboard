## 2026-11-10 to 2026-11-16 — Catch-up entry: fixing my local setup, closing security gaps, and getting tests into CI

Written on 2026-11-16, covering the week's sessions.

**Shipped:**
- #47: CSRF protection is back on. I removed `default_protect_from_forgery = false` from a course-template initializer. A `POST /reviews` with no token went from a 302 to a 422.
- #48: CI works again. The Ruby version is set to the 3.4 series, Brakeman is updated to 8.1.0, and I recorded the Rails 8.0 end-of-life warning in `brakeman.ignore`.
- #49: A request spec guards the role-escalation fix, and I removed an unused `:slug` param from sign-up.
- #51: CI now runs RSpec against a Postgres service (closes #50).

**Broke / got stuck on:**
- `bin/rails server` crashed: `cannot load such file -- concurrent/dataflow`, then a missing file in `rake`.
- All three CI jobs failed: `Unavailable version 3.4.1 for ruby on ubuntu-26.04`.
- `scan_ruby` failed: `Brakeman 8.0.6 is not the latest version 8.1.0`.
- Brakeman's first real scan found `Support for Rails 8.0.2 ended on 2026-11-07`.
- `bundle exec rspec`: `We could not find your database: repboard_test`.
- Nothing broke while adding RSpec to CI.

**How I solved it:**
- `bundle pristine` reinstalled every gem. Some had files missing, probably after a macOS and Homebrew update.
- CI uses `ruby-version: "3.4"` instead of the exact 3.4.1.
- `bundle update brakeman --conservative`, then an ignore entry with a note about the Rails EOL.
- `RAILS_ENV=test bin/rails db:prepare` created the test database. It also ran my seeds, so I wiped them with `db:schema:load`.
- I added a `postgres:15` service and `db:schema:load` to CI. I set both `DATABASE_URL` and `TEST_DATABASE_URL`, because `database.yml` reads `DATABASE_URL` with a plain `ENV.fetch` and Rails evaluates the whole file in every environment.

**Learned:**
- Pinning an exact Ruby patch in CI keeps breaking, because new runner images only keep the latest patch.
- `bin/brakeman` fails on purpose when it isn't the latest version.
- Role escalation is an authorization problem, not a validation problem. The permit list is the guard, and a test pins it so the build fails if someone widens it. A reader comment on my post made this point.
- A test only protects me if CI runs it.
